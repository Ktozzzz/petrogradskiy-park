# Архитектура сервиса

## Общая схема

```
┌────────────┐   HTTP/JSON   ┌──────────────────────────────┐   SQL/PostGIS   ┌──────────────┐
│  Frontend  │ ────────────► │  Backend (FastAPI)           │ ──────────────► │ PostgreSQL + │
│ React +    │ ◄──────────── │  REST API · AI-слой · ETL    │ ◄────────────── │ PostGIS      │
│ Leaflet    │   GeoJSON     └───────────────┬──────────────┘                 └──────────────┘
└────────────┘                              │
                                            ├── OpenAI-совместимый API (Ollama / LLM)
                                            └── Геокодер Nominatim (fallback Location Resolver)
```

## Слои backend

| Слой | Модуль | Назначение |
|---|---|---|
| API | `app/api/parks.py`, `query.py`, `analytics.py` | REST-эндпоинты, валидация параметров |
| Схемы | `app/schemas/schemas.py` | Pydantic-модели ответов и строгая схема структурированного запроса |
| Сервисы | `app/services/spatial.py`, `geojson_service.py`, `stats_service.py` | SQL-запросы к PostGIS, сборка GeoJSON, статистика и покрытие по сетке |
| AI | `app/ai/llm.py`, `parser.py`, `resolver.py`, `service.py` | клиент LLM, правила разбора текста, резолвинг локаций, оркестрация |
| Рекомендации | `app/recommendation/embeddings.py`, `recommender.py` | локальные эмбеддинги (cube), гибридный рейтинг и объяснения |
| Доступ к данным | `app/database.py`, `app/models/models.py` | SQLAlchemy engine, справочники категорий/типов/подписей |

## Цепочка запроса естественным языком

```
текст пользователя
   │
   ▼
interpret()  ──► LLM (если доступна) возвращает JSON -> валидация StructuredQuery (Pydantic)
   │             при ошибке/недоступности -> fallback: локальные правила (parser.parse)
   ▼
StructuredQuery { intent, category, poi_type, location, location2, radius_meters, limit, text }
   │
   ▼
resolve()    ──► 1) собственная БД geo_places (ILIKE + триграммный индекс)
   │             2) внешний геокодер (Nominatim), если разрешено конфигом
   │             не найдено -> ClarificationError (HTTP 422 с вопросом пользователю)
   ▼
execute()    ──► движок пространственных запросов PostGIS (KNN, ST_DWithin, geography)
   │
   ▼
QueryResponse { text, source, mode, structured, center, radius_m, count, results, poi, warnings }
```

Ключевой принцип: **AI не имеет доступа к SQL и не считает расстояния.**
Модель только классифицирует запрос в строгую схему, которую валидирует backend
(`intent` — Literal-значение, координаты — Field с диапазонами, radius — 1…50000 м).

## Гибридный рейтинг рекомендаций

```
score = 0.50·semantic + 0.30·spatial + 0.20·category
```

- **semantic** — близость эмбеддинга запроса к эмбеддингам объектов (название + описание + темы);
  векторы хранятся в колонке `cube` с GiST-индексом, расстояние — `<->`.
- **spatial** — экспоненциальный спад от расстояния до точки отсчёта (учёт пешей доступности).
- **category** — совпадение категории/типов точек интереса с намерением запроса.

Веса вынесены в `.env` (`RANK_WEIGHT_*`) и нормализуются в `config.ranking_weights()`.
Каждый результат содержит подробное объяснение (найденные совпадения тегов, расстояние,
тип объекта) — это видно в интерфейсе в карточке рекомендации.

## Хранение геометрии

| Таблица | Тип геометрии | Индекс |
|---|---|---|
| `parks` | MultiPolygon (контуры из OSM), `centroid` (Point) | GIST (geometry), GIST (centroid), GIST (ll_to_earth) |
| `poi` | Point | GIST |
| `park_roads` | LineString | GIST |
| `park_exits` | Point | GIST |
| `districts` | MultiPolygon | GIST |
| `geo_places` | Point | GIST, GIN (pg_trgm) |

Расстояния считаются в метрах через тип `geography` (точный пересчёт на сфере),
быстрый отбор — по индексам `geometry` (ST_DWithin) и `ll_to_earth` (KNN-куб).

## ETL

1. `scripts/fetch_osm.py` — 5 запросов к Overpass API (границы района, зелёные объекты,
   точки интереса, дорожки, ориентиры). Ответы сохраняются «как есть» в `data/raw/`
   для воспроизводимости.
2. `scripts/import_data.py` — очистка и дедупликация, классификация категорий,
   отбор объектов, попавших внутрь контуров района, вычисление производных полей
   (площадь, периметр, счётчики), построение индексов, отчёт о выполнении требований.
3. `scripts/setup_db.py` — создание БД, расширений (`postgis`, `cube`, `pg_trgm`) и миграций.

## Фронтенд

- `MapView` — императивная обёртка над Leaflet: слои «контуры/центроиды районов»,
  «парки», «дорожки», «входы/выходы» (стрелки), «условные знаки точек интереса»,
  «нумерованные результаты». Переключатель «Точки / Полигоны» меняет отображение парков.
- `Sidebar` — поиск, карточка объекта, пространственные формы, статистика, умные запросы
  с подсказками, рекомендации с объяснением рейтинга, легенда условных знаков.
- Состояние приложения — React-хуки; данные — через `src/api.ts` (типизированный клиент).

## Отказоустойчивость

- AI-модель недоступна -> запрос разбирается локальными правилами, карта работает.
- Геокодер недоступен -> используются только названия из собственной БД `geo_places`,
  иначе — вежливый запрос уточнить точку отсчёта (HTTP 422).
- Фронтенд не собран -> backend работает как чистый API с `/docs`.
